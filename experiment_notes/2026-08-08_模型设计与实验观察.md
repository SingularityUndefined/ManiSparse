# 2026-08-08：模型设计与实验观察

## 当前结论

当前 unrolled Graph-ADMM 模型在训练集和单一 validation 时间段上可以持续降低 loss 或预测指标，但这种改善并不稳定迁移到更晚的 test 时间段。已有实验还显示：**去掉 Theta regularizer 的 ablation 在 PEMS03 与 PEMS08 上都优于当前包含 Theta 的版本**。因此，现阶段不应把 Theta 分支视为已验证有效的模块；它更可能是当前性能、稳定性和时序泛化问题的来源之一。

这不等价于“图先验一定无用”。更准确的表述是：在目前的尺度、候选邻居、优化路径和模型选择协议下，Theta 分支带来的增益不足以抵消它引入的误差、自由度和数值风险。

## 已观察到的实验现象

### 1. PEMS03：训练继续改善，validation 较早恶化

`kaloBW1_deflateBW1` 的 PEMS03 run 中，validation loss 在约 epoch 15 取得最佳值，之后训练 loss 仍缓慢下降，而 validation loss 明显上升。这是直接的训练后期过拟合/优化漂移信号。该 run 同时启用了可微 Local Kalofolias 与可微 deflation，因此梯度会穿过多 mode CG、正交化和下一 block 的 Theta 估计链路。

### 2. PEMS08：validation 改善没有迁移到 test

PEMS08 的同类 full-backward run 中，validation loss 和 validation forecast RMSE 在后期继续改善，但每 10 epoch 载入 validation-best checkpoint 的 test 指标持续变差：例如 test loss 从 epoch 19 checkpoint 的约 10.43 上升到 epoch 69 checkpoint 的约 11.74，test RMSE 从约 31.38 上升到约 34.68。

日志表明 checkpoint 选择逻辑正常工作：测试时确实加载了当时的 validation-best checkpoint，而不是错误复用早期模型。因此这是 validation 时间段与最终 test 时间段的失配，而非简单的评估代码错误。

### 3. 较早的 PEMS08 local-Kalofolias run 更稳定

2026-08-04 的 `thetaK8` run 使用 Adam、batch size 20、Local Kalofolias、deflation 和 detached 辅助求解路径。在该 run 中，test loss/RMSE 大体随训练改善，到 epoch 60 附近达到较好值，epoch 70 才出现轻微回升。

它是有价值的参考，但不能单独证明 `thetaK=8` 是唯一原因：与后续 run 相比，同时变化了 Theta 邻居数、batch size、full-backward 开关、空间 penalty 参数化、参数投影和代码版本。

### 4. Theta ablation 在两个数据集都更好

此前工作中，移除 Theta regularizer 的 ablation 在 PEMS03 和 PEMS08 均优于包含 Theta 的当前模型。这是目前最强的设计反馈：Theta 分支至少在默认设定下没有形成可复现的净收益。

## 为什么去掉 Theta 可能更好

### Theta 是一个额外且强的数据依赖先验

每个 batch、每个中间 block 都会从当前重建信号或 deflated modes 重新估计 Theta。它不是固定物理图，而是随当前预测误差变化的图算子。若重建早期存在偏差，Theta 会把该偏差转换成后续 block 的空间正则化方向，形成“错误重建 → 错误图 → 更强错误平滑”的反馈。

### 物理/学习图与 Theta 可能重复甚至冲突

模型已经包含 learned graph (L_u)、有向时间图、空间/时间 embedding、feature extractor 和 ADMM 更新。Theta 再增加一个空间图先验；如果它的局部邻域或权重与 learned graph 不一致，两个拉普拉斯可能竞争而非互补。此时 Theta ablation 更好，意味着现有 learned graph 已足够，或 Theta 的尺度/图结构不合适。

### Theta 的尺度没有与其他算子充分校准

ADMM 使用的空间项可写为：

\[
\mu_u L_u + \lambda_\theta \Theta.
\]

即使 \(\mu_u\) 与 \(\lambda_\theta\) 为正，不同 batch 的 Theta 谱尺度、度分布和局部候选数仍会变化。相同的 \(\lambda_\theta\) 在不同 batch 上对应不同强度的平滑，容易造成过度平滑、欠平滑或不稳定的条件数。

### detached 与 full-backward 都有潜在问题

- detached 路径：Theta 会影响 forward，却不能因最终 prediction loss 直接学习“何时不该相信 Theta”；
- full-backward 路径：梯度会穿过 Kalofolias 迭代、deflation CG 和正交化，信号长、方差高且对特定训练/validation 时间段适配更强。

因此，前者可能是不可控先验，后者可能是过度可适配的先验。

### 候选宽度 K 可能改变了 bias-variance trade-off

`thetaK=8` 比 `thetaK=10` 更稀疏，可能减少错误边和过度平滑；也可能更接近 PEMS08 的有效局部几何。需要在同一代码、同一 batch size、同一 optimizer 下直接比较 K8 与 K10，不能以跨版本日志作结论。

## 当前模型设计的薄弱点

1. **模块过多但缺少增益归因。** 当前模型同时学习 graph weights、Theta、CG step sizes、ADMM penalties、skip weights、embedding 与 extrapolator。若没有逐模块同协议 ablation，很难判断性能来自哪里。
2. **Theta 是非平稳算子。** 它随 batch 和 block 变化，但 \(\lambda_\theta\) 没有根据 Theta 的谱范数、平均度或 trace 做显式归一化。
3. **deflation 的目标与预测目标不完全一致。** deflation 解的是 \(I+\mu_uL_u+\lambda_\theta\Theta\) 的正交 mode，而不是完整 ADMM 的数据项和时间项；它服务于下一 block 的图估计，未必直接服务于 forecast loss。
4. **空间系数约束带来稳定性与表达能力的取舍。** 当前 \(\mu_u\) 与 \(\lambda_\theta\) 使用正总量与 sigmoid 分配，保证有效空间算子更接近正定，但也禁止两个项独立调整总强度或符号。独立系数 ablation 可以验证该约束是否过强，但存在 CG 不定和数值发散风险。
5. **单一 validation 时间段不足以代表未来。** 时间顺序切分下，60–80% 的 validation 可能是一个不同运行状态；持续选择其最优 checkpoint 会对该时段过拟合，却不能保证 80–100% test 改善。
6. **训练目标与模型选择指标需更一致。** 当前 raw Huber loss 与报告时非负截断后的 RMSE/MAE 不完全同一目标；最终 checkpoint 选择应优先使用部署目标对应的预测区间指标，例如 forecast RMSE/MAE 或 masked forecast Huber。

## 建议的解决路径

### 第一优先级：建立可信的比较协议

1. 固定当前代码、seed、batch size、optimizer、学习率和数据切分，只改变一个因素。
2. 保留最终 20% test 全程不参与选择；在 test 之前采用 expanding-window / rolling validation，例如 `[0,50)→[50,60)`、`[0,60)→[60,70)`、`[0,70)→[70,80)`。
3. 对每个配置记录每个 fold 的最佳 forecast RMSE/MAE、最佳 epoch、均值和最差 fold。优先选择跨时间段最稳健的配置，而不是某个 validation 段最低 loss。

### 第二优先级：先判断 Theta 是否值得保留

最小必要实验：

1. 当前代码下比较 `Theta ablation` 与 `Theta enabled`；
2. 对 Theta enabled 固定所有其他项，只比较 `thetaK=8` 与 `thetaK=10`；
3. 对表现较好的 K，比较 detached 与 full-backward；
4. 只有在 Theta enabled 能稳定超过 Theta ablation 后，再继续扩展复杂度。

若 Theta ablation 仍在两个数据集和多个时间 fold 上更好，应把 Theta 从默认模型中移除，或降级为可选组件，而不是继续围绕它调参。

### 第三优先级：让 Theta 成为更温和、可控的先验

可依次尝试：

1. **残差门控：** 用有界 gate 控制 Theta 项，例如从很小的 \(\lambda_\theta\) 初始化，让模型学习是否使用 Theta；
2. **尺度归一化：** 对 Theta 以平均度、trace 或估计谱范数归一化，再乘可学习系数；
3. **EMA / 跨 batch 平滑：** 降低每个 batch 重估图造成的非平稳性；
4. **只在后期 block 使用 Theta：** 避免初期重建误差污染图估计；
5. **限制图变化：** 对相邻 block 或相邻 batch 的 Theta 加一致性正则，避免图快速漂移；
6. **更保守的局部邻域：** 先以 `thetaK=8` 为中心进行小范围搜索，并检查 Theta precision/recall 与实际预测指标的关系。

### 第四优先级：稳定性与参数化消融

当前已准备的 PEMS08 消融覆盖：

- detached / full backward；
- ADMM penalty 正值投影开/关；
- \(\mu_u,\lambda_\theta\) 正总量-sigmoid 耦合 / 独立非约束参数。

其中独立参数版本的目的不是直接追求更高分数，而是验证“正耦合是否限制了有效解”。必须同时记录：`mu_u`、`lambda_theta`、各 `rho` 的范围、CG 残差或异常、NaN/Inf，以及 train/validation/test forecast 指标。若独立版本更好且仍稳定，再考虑较柔和的替代参数化，例如正的独立 softplus 系数，而不是允许任意负值。

## 建议的实验优先顺序

1. 当前代码、full backward、`thetaK=8` 与 `thetaK=10` 的直接对照；
2. 当前代码、Theta ablation 与上述更优 K 的 Theta enabled 对照；
3. 对更优 K 跑 detached/full-backward 对照；
4. 跑空间 penalty 耦合/独立与 ADMM projection 的消融；
5. 引入 rolling validation，再复验最优两到三个配置。

在任何新复杂分支稳定优于 Theta ablation 之前，优先维护更简单的 Theta-free baseline。模型设计的下一步应是减少未验证自由度、建立可复现增益，而不是继续叠加新的图估计或求解模块。
